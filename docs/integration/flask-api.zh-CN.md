# Flask Core 与 API v1

> 语言：**简体中文** | [English](flask-api.md)

MaplesAdventure 内部开发中功能，不是独立模组。永久玩家 Attachment `maplesadventure:player_flasks`（数据版本 1、死亡复制）保存全部次数。ItemStack 只是可重复使用的入口，复制、交易或丢弃瓶子不会转移成长或次数。登录／复活时，背包有空间则补发缺失入口物品。不加入配方、材料世界生成、空瓶或耐久次数。

## 数据与规则

`FlaskSnapshot` 不可变，包含总容量 4–14、共享强化 0–12、红／灰分配及剩余次数。分配之和始终等于容量，剩余不超过各自分配。`FlaskState.normalize` 是唯一修复规则：限制容量／强化／红瓶分配，推导灰瓶分配，再限制剩余次数。已有记录不会被重新初始化。

新玩家：无 Iron's 为 4/0，有则为 3/1。移除 Iron's 保留容量与强化，把分配和**剩余次数**归并到红瓶，不额外补充次数；重新安装不强制重新分配。

## 篝火接入

补充监听 `MaplesBonfireRestCompletedEvent`，不创建第二套休息／Reset 事务。新增的公开 `MaplesBonfireRespawnEvent` 只在已验证的内置篝火复活真正完成后发布。Clone 仅复制数据，与 keepInventory 无关；回退 Vanilla 复活不补满。

功能 ID：`maplesadventure:flask_allocation`、`maplesadventure:flask_upgrade`。新篝火默认配置两项。休息主菜单只显示一个“强化原素瓶”入口；下一级页面并列显示“强化使用量”与“提升恢复量”卡片，各自包含当前／下一级数值、材料持有／需求和独立确认按钮，共用原有服务端强化事务。分配仍单列，仅在魔力适配器可用时显示。页面复用已有瓶子与材料素材，无高斯模糊，按窗口大小缩放，不修改篝火动画或镜头。

FeatureDataVersion 3 在读取时将旧 `flask_capacity`、`flask_potency` 合并为 `flask_upgrade`。旧 ID 继续作为管理员配置别名，启用／禁用任意别名现在控制合并入口；重复别名仅生成一项。其他功能、激活状态和玩家瓶子成长不变。原先未配置的篝火仍不擅自启用，可用 `/ma bonfire feature <x> <y> <z> maplesadventure:flask_upgrade true` 配置。

菜单请求包含单次服务端 nonce 和有界动作 ALLOCATE、UPGRADE_CAPACITY、UPGRADE_POTENCY 或 CLOSE，只有分配使用红／灰请求值。页面、篝火引用和基线在服务器保存，提交重查 RESTING 授权、放置代数、维度、功能可用性和超时。分配授权不能购买强化，强化授权不能重新分配。不接受客户端容量、强化、价格或材料持有量。成功和失败提交都轮换 nonce，待确认时两个强化按钮同时锁定。响应携带已消费 nonce，延迟响应不能重新打开已关闭页面。强化保存受影响背包槽及旧状态，精确扣材料再写新状态，提交异常时同时回滚，之后同步；扩展事件在提交后发布。

## 动作与兼容

`FlaskUseController` 跟踪活跃动作：总计 30 ticks，第 14 tick 一次性提交。`FlaskRecoveryService` 在随后的六个服务器 ticks（15–20，即 0.3 秒）发放提交的总回复量。每步在当前资源上累加并限制至当前最大值，不用目标值插值覆盖期间受到的伤害。松开鼠标不取消；换掉手中物品、受伤、硬直取消动作，但已提交回复继续。死亡、退出、换维度、补充、非法生命周期、SCRIPTED 取消和停服清除待回复任务；不持久化，不复制给重生后的玩家实体。生效前中断不恢复、不扣次数；生效后不退款。可转动视角和缓慢移动，禁止冲刺、近战及冲突物品交互。现有 Epic Fight 技能施放 Hook 在喝瓶时拒绝技能；Iron's 的公开 SpellPreCastEvent 拒绝新施法。其他战斗附属应在自己的硬直／处决语义中调用取消 API。

使用 Vanilla DRINK 动画和实体来源饮用音效作为占位，替换位置集中在 Item／FlaskPresentation。不包含最终 VFX 或 Epic Fight 专用动画。最小 `FlaskReleaseMixin` 只阻止松开使用键取消独立喝瓶动作；结束通过 `stopUsingItem` 清理，不改变其他物品。

`FlaskManaBridge` 仅在实际 modid `irons_spellbooks` 存在时反射加载 `IronsFlaskAdapter`，修改真实 MagicData 并发送 SyncManaPacket。Core／公开签名不依赖 Iron's 或 Epic Fight 类型。无 Iron's 时保留稳定灰瓶注册项，但功能停用，创造栏、HUD、分配菜单隐藏；存档背包已有灰瓶可以作为无功能物品保留。

## 公开接口

`dev.maplesadventure.api.flask.FlaskApi` 提供 `getState`、`isUsingFlask`、总容量、强化等级、红／灰分配与剩余次数、恢复量查询，以及仅服务端的 `cancelUse(player, reason)` 和 `refill(player, reason)`。不提供任意设置成长值的方法。快照脱离内部状态，客户端只查询已同步的本地玩家，不查询其他玩家隐私数据。

`FlaskEvents.Start`／`.Effect` 是可取消的逻辑服务端事件，Effect 可修改有限、有界、非负**总回复量**，扣次数前仅采样一次，不是每一步回复都发事件；取消会结束动作且不扣次数。`.Finish`、`.Cancel`（含 effectApplied）、`.Refill`、`.Upgrade` 是通知。事件异常记录日志，动作回调失败关闭；NeoForge 不保证抛错监听器之后的监听器继续执行。可选资源恢复适配器抛错后停止剩余回复，不退款、不重试，因为恢复可能已经执行。Mana 的六步增量使用既有资源同步，不发送六次完整 FlaskState。

补充原因：BONFIRE、ENEMY_GROUP、BOSS_DEFEAT、SCRIPTED。当前仅篝火自动补充，其他是扩展意图，不实现杀怪补瓶、法术记忆或统一篝火菜单。

协议 **27** 包含合并强化页、有界动作和关联响应，客户端与服务端需一起更新。仅变更、登录、复活、换维度同步，不逐 Tick 全量广播。HUD 显示快捷栏／副手瓶子的分配池次数。

## 瓶子表现

七档 `hpflask`／`mpflask` 原图原样复制到 `textures/gui/flask/icons`，**1 最满、7 最空**，按剩余／分配次数选择，不按总容量选择。GUI 独立纹理绘制保留原图宽高比，避免把不规则尺寸图片拼入方块图集而降低全局 mipmap 等级。强化材料继续使用已有素材。远端玩家未同步私有次数，因此手持默认显示满瓶，不会错误跟随本地玩家的次数变化。

手持、地面、展示框使用独立体素模型：红瓶为长颈冠形瓶塞，灰瓶为宝石瓶塞与金属箍。不同模型档位逐步降低液面。`models/item/flask/*_body_*.json` 可作为 Java Block/Item 模型在 Blockbench 编辑。颜色、透明玻璃和自发光以游戏内 NeoForge 扩展为准，不支持这些扩展的编辑器可能显示不透明玻璃或无染色表面。不依赖第三方模型库。

强化页展示同一套立体模型；分配页展示双瓶、左右调整、分配数字，以及与共享容量一致的小瓶刻度。分配预览仅显示确认补满后的外观，提交前不改变游戏状态。八帧已有发光蒙版在绘制时染成金色／蓝色半透明光晕，所有原图像素保持不变。本次视觉调整不改变协议、平衡数值、休息／Reset 事务或篝火镜头。

液体模型面使用 120/255 Alpha，金属保持不透明。光晕使用金／蓝加色混合，绘制完恢复先前渲染状态。分配小瓶使用提供的剪影 Alpha 蒙版而非黑色 RGB，已分配染金／蓝，其余染灰。分配确认即使未调整，也在服务端成功后才返回篝火菜单；Esc 丢弃草稿。强化购买成功继续停留。

篝火来源的升级、分配、强化页共用 `BonfireSubscreenTransition`：透明离屏页面整体合成，320ms 内向左移动 24 GUI 像素并淡入，离开时向右移动并淡出。过渡期间禁用业务输入，结束后只切换一次页面。不引入世界模糊，不改变休息／Reset、镜头和角色动画。非篝火升级入口保留自己的表现；未来子页面可复用同一组件，而不把服务端授权交给动效管理。

## 可选 Souls Combat HUD 兼容

客户端适配目标为 `souls_combat_hud` **1.3.1 NeoForge**。其九格快捷道具选择器识别原素瓶，仅有魔力支持时识别灰瓶。保留 Souls HUD 显式道具／自动使用黑名单，不扫描背包其他格。不修改第三方 JAR、配置、物品注册、存档格式或网络协议。

仅适配可用时隐藏原独立 Flask HUD。次数由当前快捷道具决定，不跟随手持武器。`剩余 / 分配` 放在主框**左侧** 3 个 HUD 局部像素处，文字底边高于框底 1 像素；名称保持原位和原淡出，所有预览行也保持原位。位置跟随真实 HUD 变换；极端自定义布局无法容纳时隐藏次数，不覆盖或移动其他元素。F1 或关闭装备／道具 HUD 时一起隐藏。不支持或未安装该 HUD 时保留独立显示，兼容失败只警告一次。

快捷使用只发送一次普通物品使用意图，等待既有服务端 Flask 同步，包括明确的拒绝快照。等待／饮用期间拦截重复使用。结束、拒绝及中断后，仅在仍持有槽位控制权时恢复原快捷栏槽位；手动换槽、死亡、断线、换维度取消恢复。等待响应安全超时为 100 客户端 tick。不预测次数和恢复量，第 14 tick 扣次／六步回复仍由服务端负责。

快捷键继续由 Souls Combat HUD 管理。其默认 `G` 使用键可能与 Curios 饰品栏冲突，同时安装时请在 Minecraft 按键设置中重绑其中一项。适配器不改动两者的键位，也不绕过 Souls HUD 对 Epic Fight 手持物品切换的限制。

隔离联调使用 `-PwithSoulsCombatHud=true -PsoulsCombatHudJar=<本地 JAR>`，NeoForge 版本为 HUD 所需的 `21.1.244`，不提高 MaplesAdventure 声明的最低版本。可选 Mixin 仅客户端加载；专服或未安装 HUD 的环境不链接它的类。

三个 Hook 使用独立的可选 Mixin 配置。加载前先通过字节码核对 HUD 版本与全部注入方法签名，不提前加载目标类；目标缺失或不兼容时整体跳过三个 Hook。客户端再验证标记与反射 API，通过后才启用适配；失败时只警告一次并保留独立显示。此兼容检查不干预 Phase／Bonfire 的其他 Mixin。

## 开发检查

OP 命令：`/ma flask status [player]`、`refill`、`reset`、`set_capacity <4–14>`、`set_potency <0–12>`、`set_allocation <crimson> <ashen>`。修改命令以目标玩家身份执行，仅用于调试，不是生存升级入口。

单元测试覆盖完整冻结表、边界、所有分配、归一化、NBT 复制、可选模组迁移、动作时点、图标映射、Codec 和 API 边界。隔离世界使用 `runServer -PweaponRegression=true` 后运行 `flaskregression`；合成服务器夹具检查真实控制器、资源修改和材料事务，不能替代真实客户端动画／菜单、重启与多人验收。
